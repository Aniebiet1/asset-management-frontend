Item details and fixes

F-01 · Two-factor bypass on the platform console Fixed

Pre-auth tokens shared a signing secret with session tokens and the session check verified only the signature. Fixed by giving every token type its own JWT audience (src/lib/jwt.ts). Before: platform read routes returned 200 to a pre-auth token. After: 401 everywhere. Action: deploy to production; platform admins sign in once more after deployment.

F-02 · Public organization creation

POST /api/organizations is unauthenticated. Beyond bypassing onboarding, because emails are unique platform-wide an attacker could pre-register a prospect's email and block their onboarding. Fix: delete the route (the frontend uses POST /api/platform/orgs) and move the integration tests to the platform route.

F-03 · Console authenticator code replay

Customer sign-in stores the last accepted time-step; the console passes null. Fix: add totp_last_used_step to platform_admins and pass it through, mirroring the customer implementation.

const result = verifyTotpCode(secret, code, admin.totpLastUsedStep);
if (result.valid) await db.update(platformAdmins).set({ totpLastUsedStep: result.step }).where(eq(platformAdmins.id, admin.id));

F-04 · Console account lockout

Only the per-IP rate limit applies, which distributed guessing avoids, and failed console sign-ins are not logged. Fix: add failed_login_attempts / locked_until to platform_admins, reuse the customer lockout (5 attempts, 15 minutes) and log failures to the platform admin log.

F-05 · Access after deactivation

Access tokens are verified by signature only, so deactivation or a role change takes effect when the token expires. Fix: in loadOrgContext also load the user, reject inactive users and use the stored role; revoke refresh tokens on deactivation; add the same check to authenticatePlatformAdmin.

F-06 · Last super admin can be removed

PUT/DELETE /api/people/:id let any admin change any role, including all super admins and themselves. Fix: only a super admin may grant or remove super_admin; refuse any change leaving zero active super admins; forbid self-demotion and self-deactivation.

F-08 · Account discovery

Sign-in takes about 137 ms for a real account and 6 ms for an unknown email; the sign-in page's workspace lookup also confirms whether an email is registered (rate-limited). Fix: verify against a dummy argon2 hash when no user exists; optionally return default Tecres branding instead of 404 from the lookup.

F-09 · Password policy

Fix: minimum 12 characters and a breached-password check (Have I Been Pwned range API), per NIST SP 800-63B. Mandatory two-factor limits current exposure.

F-10 · Oversized request handling

The body-size limit works, but the error handler reports it as a 500 and logs it as a crash. Fix: in errorHandler.ts, pass through errors with a 4xx status (for example 413 entity.too.large).
